# Transport

> **Host-owned.** The SDK is transport-agnostic, but the transport is chosen and constructed by
> the host shell — mini apps never construct or configure it. This page is background reading so
> you understand what runs underneath `sdk.*`.

The default is `postMessage` + `CustomEvent`; other transports can be supplied by the host at construction.

## Interface

```typescript
interface Transport {
  start(onMessage: (msg: PlatformMessage) => void): void;
  stop(): void;
  send(message: PlatformMessage): void;
  getDebugInfo?(): { started: boolean; pinnedOrigin?: string | null };
}
```

## Built-in Transports

| Transport | Source | Use case |
|---|---|---|
| `DefaultTransport` | `transport/default-transport.ts` | Browser iframe / WebView. `postMessage` + `CustomEvent (gov-platform-event)` with origin pinning. |
| `WebSocketTransport` | `transport/websocket-transport.ts` | `new WebSocketTransport({ url, protocols, socket })` - remote host. |
| `BroadcastTransport` | `transport/broadcast-transport.ts` | `BroadcastChannel("gov-platform-sdk")` - multi-tab. |
| `MessagePortTransport` | `transport/message-port-transport.ts` | `MessagePort` / Web Worker. |
| `SsrTransport` | `transport/ssr-transport.ts` | No-op for SSR / static rendering. |

## Origin Pinning

`DefaultTransport` learns the host origin on the first valid message and pins it (`allowedOrigin`). Subsequent messages from other origins are dropped. It accepts `allowedOrigin` (pin upfront, or leave undefined to learn), `allowCustomEvent` (CustomEvent fallback for Flutter WebView), and `warnOnBroadcast` — all set by the host, not by mini apps.

## Custom Transport

Custom transports are a host-shell concern, passed via the SDK options at construction:

```typescript
// Host-side only. Normal mini apps never construct the transport directly —
// the PlatformSDKProvider reads the already-connected instance from window.__GSA_SDK__.
```

See `transport/transport.types.ts` for `TransportDebugInfo` and `DefaultTransportOptions`.
