# Streaming

A streaming call answers in pieces instead of all at once. Use it for chat
replies, long exports and progress output.

Ask for one with `stream: true`:

```js
const stream = await sdk.api.request("POST", {
  path: "/v1/chat",
  body: { message: "Hello" },
  stream: true,
});
```

You get a `StreamBuilder`. It carries raw bytes from your backend, exactly as
your backend sent them. The SDK does not interpret them.

## Reading events

Most backends send Server-Sent Events. `parseSseStream` turns those bytes into
objects:

```js
for await (const event of sdk.stream.parseSseStream(stream.iterate())) {
  switch (event.type) {
    case "token": append(event.text); break;
    case "done":  finish();           break;
    case "error": showProblem(event); break;
  }
}
```

`sdk.stream.parseSseStream` is on the injected SDK, so there is nothing to
import.

Each event is `{ type, ...fields }`. The `type` comes from the SSE `event:`
line, and the rest from its `data:` line. Your backend chooses those names.

Three things worth knowing:

- An event split across two chunks is reassembled for you.
- `data:` that is not JSON arrives as `{ text: "<raw>" }`.
- `parseSseStream` never throws. A backend `error` event is yielded last, then
  the loop ends. Handle `error` inside the loop.

## Reading raw chunks

If your backend does not send SSE, read the chunks yourself:

```js
for await (const chunk of stream.iterate()) {
  // chunk is a string or a Uint8Array
}
```

A stream has **one consumer**. Iterate it once.

## Stopping early

```js
const controller = new AbortController();

const stream = await sdk.api.request("POST", {
  path: "/v1/chat",
  body: { message },
  stream: true,
  signal: controller.signal,
});

cancelButton.onclick = () => controller.abort();
```

Aborting tells the host to stop the stream, so your backend can stop working.
Always abort when the citizen navigates away.
