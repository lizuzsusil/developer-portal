# Navigation (`sdk.navigation`)

Requests host-level route transitions and syncs the mini app's internal router with the host back button. The host owns browser history - never assign `location.hash` directly; route through your framework router (or `history.pushState` + manual notification) instead.

---

## Public Methods

### `navigate(target)`

Requests the host platform to navigate - typically to a route in another mini app.

**Signature:** `navigate(target: NavigationTarget): Promise<void>`

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `target.app` | `string` | Yes | - | Target mini-app id (or `"shell"` for host routes). |
| `target.route` | `string` | Yes | - | Route path inside the target, e.g. `"/services/passport"`. |
| `target.params` | `Record<string, string>` | No | - | Route params forwarded to the target. |
| `target.replace` | `boolean` | No | `false` | Replace the current history entry instead of pushing. |

<CodeTabs
  typescript={`await sdk.navigation.navigate({
  app: "services-mini-app",
  route: "/passport",
  params: { purpose: "renewal" },
});`}
  javascript={`await sdk.navigation.navigate({
  app: "services-mini-app",
  route: "/passport",
  params: { purpose: "renewal" },
});`}
/>

For deep-linking *into* your own mini app from outside, the host passes `{ initialPath }` to your `mount()` - see [Links](/docs/sdk/links).

### `getCurrent()`

Queries current navigation state from the host.

**Signature:** `getCurrent(): Promise<NavigationState>`

**Returns:** `NavigationState`

| Field | Type | Description |
|---|---|---|
| `current` | `string` | Current route string. |
| `history` | `string[]` | Route history stack. |

<CodeTabs
  typescript={`const navState = await sdk.navigation.getCurrent();
console.log("Current route:", navState.current);`}
  javascript={`const navState = await sdk.navigation.getCurrent();
console.log("Current route:", navState.current);`}
/>

### `router.back(consumed?)`

Answers the host's held back-press: reports whether the mini app's internal router consumed it (`true`) or the host should take over (`false`, i.e. at root). Subscribe via `navigation.back.requested`.

**Signature:** `router.back(consumed?: boolean): Promise<NavigationRouterResult>`

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `consumed` | `boolean` | No | `true` | `false` means "I'm at my root, you take over". Bare booleans and missing payloads also default to `true`. |

**Returns:** `{ consumed: boolean }`

<CodeTabs
  typescript={`sdk.on("navigation.back.requested", async () => {
  // Derive from your own router ("am I at root?"), not window.history.
  const consumed = currentPath !== "/";
  await sdk.navigation.router?.back?.(consumed);
  if (consumed) goBackOneStep();
});`}
  javascript={`sdk.on("navigation.back.requested", async () => {
  // Derive from your own router ("am I at root?"), not window.history.
  const consumed = currentPath !== "/";
  await sdk.navigation.router?.back?.(consumed);
  if (consumed) goBackOneStep();
});`}
/>

### `router.push(consumed?)`

Tells the host the mini app pushed an internal route step, so the next back press is worth asking about.

**Signature:** `router.push(consumed?: boolean): Promise<NavigationRouterResult>`

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `consumed` | `boolean` | No | `true` | Whether the push represents navigable history. |

<CodeTabs
  typescript={`await sdk.navigation.router.push(true);`}
  javascript={`await sdk.navigation.router.push(true);`}
/>

Emit `navigation.route.changed` with root-derived `canGoBack` on every route change to keep the host's back-button policy in sync. See the framework guides ([React](/docs/integration/react), [Vue](/docs/integration/vue), [Svelte](/docs/integration/svelte), [Solid](/docs/integration/solid)) for the full bidirectional pattern.

:::warning Raw hash writes
Never navigate by assigning `location.hash` - in Chrome this fires a spurious `popstate` that the host shell mistakes for a back press (see the [Svelte guide](/docs/integration/svelte)).
:::
