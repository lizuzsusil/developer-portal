# Errors

All SDK failures are `SdkError` subclasses with a `code` and optional `retryable` flag.

## Hierarchy

```
SdkError
├── HandshakeError        - handshake rejected / timeout / version mismatch
├── TransportError        - transport send/start failure
├── ProtocolError         - malformed wire message
├── TimeoutError          - per-request timeout (retryable)
├── RequestCancelledError - AbortSignal aborted
├── StreamCancelledError  - StreamBuilder.cancel()
├── HttpClientError       - 4xx (not retryable)
└── HttpServerError       - 5xx (retryable)
```

## Codes

Common `SdkError.code` values: `HANDSHAKE_FAILED`, `CAPABILITY_NOT_SUPPORTED`, `SDK_NOT_INITIALIZED`, `SDK_ALREADY_DESTROYED`, `CIRCUIT_OPEN`, `REQUEST_CANCELLED`, `STREAM_CANCELLED`.

## Guards

Error classes and guard helpers (`isTimeout`, `isRetryable`, …) live in the SDK runtime, which
mini apps never import. Branch on the error shape instead - every SDK failure carries a `code`
and usually a `retryable` flag:

```typescript
try {
  await sdk.auth.getUser();
} catch (err) {
  const code = (err as { code?: string } | null)?.code;
  const retryable = (err as { retryable?: boolean } | null)?.retryable === true;
  if (code === "REQUEST_CANCELLED" || code === "STREAM_CANCELLED") return; // unmount path
  if (code === "TIMEOUT" || retryable) { /* retry or show spinner */ }
  console.log(code); // string | undefined
}
```

`CAPABILITY_NOT_SUPPORTED` is thrown when the mini app calls a namespace the host did not grant during handshake - gate such calls with `sdk.device.isSupported()` (or the deprecated `sdk.permissions`, see [Permissions](/docs/sdk/permissions) - deprecated) first. Auth-family codes (`AUTH_FAILED | AUTH_REQUIRED | UNAUTHENTICATED | FORBIDDEN`) arrive the same way, on `err.code`.
