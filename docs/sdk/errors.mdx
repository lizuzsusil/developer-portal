# Handling errors

Every SDK call rejects with an error carrying a `code`. Branch on the code —
the SDK is injected by the platform, so there is nothing to import.

```js
try {
  const user = await sdk.auth.getUser();
} catch (err) {
  console.log(err.code, err.message);
}
```

## The codes you will actually see

| Code | What happened | What to do |
|---|---|---|
| `CAPABILITY_NOT_SUPPORTED` | You called a namespace your mini app was not granted | Offer a fallback. Check `sdk.capabilities` first |
| `TIMEOUT` | The platform did not answer in time | Safe to retry. The SDK already retried once |
| `REQUEST_CANCELLED` | You aborted it | Usually nothing — the citizen moved on |
| `CIRCUIT_OPEN` | Too many recent failures, calls are paused | Show a "try again shortly" message |
| `HANDSHAKE_FAILED` | The SDK never connected to Sewa | Your app is running outside Sewa, or is not registered |

## A capability you were not granted

This is the one most mini apps meet first. Your app is granted a specific set of
namespaces, and anything outside it fails immediately, without a round trip:

```js
if (!sdk.capabilities.includes("device")) {
  showManualAddressForm();
  return;
}

try {
  const loc = await sdk.device.location();
} catch (err) {
  if (err.code === "CAPABILITY_NOT_SUPPORTED") showManualAddressForm();
}
```

Checking `sdk.capabilities` up front is better than catching: you can render the
right UI instead of an error after the fact.

## Retrying

The SDK already retries timeouts and 5xx responses with backoff before the
error reaches you. By the time you see one, an immediate retry will probably
fail too. Give the citizen a button rather than looping.

Your backend's own status does not throw. `sdk.api.request` returns it as
`res.status`, so check that before using `res.data`.

## Errors from your own backend

Your backend's response body reaches you unchanged on success. Design it so
your frontend can tell a business outcome from a failure:

```js
const res = await sdk.api.request({ method: "POST", path: "/v1/quota", body });

if (res.data.error) {
  showFieldErrors(res.data.errors);   // a business answer, not a failure
  return;
}
render(res.data);
```

## When you are not inside Sewa

Opened directly in a browser tab there is no shell to connect to, so the SDK
never reaches `ready`. Say so plainly rather than showing a blank screen:

```js
whenSdkReady()
  .then(start)
  .catch(() => showMessage("Open this from the Sewa app."));
```

`whenSdkReady` is the small poll helper from
[Getting Started](/docs/getting-started).
