# Plugins & Module Registry

> **Mostly host-side.** `sdk.usePlugin`, `registerModule`, and friends are methods on the injected
> instance, so they are callable from a mini app - but plugins are normally installed by the host
> before it hands you the SDK. Custom modules additionally require host support for the new
> namespace. Read on for what each piece means; reach for them only when the host docs tell you to.

Extend the SDK without forking it.

## Plugins - `SdkPlugin`

```typescript
interface SdkPlugin {
  name: string;
  install(ctx: { sdk: MiniAppSdk; rpc: RpcClient; logger: Logger }): void;
  onInitialize?(): void | Promise<void>;
  onDestroy?(): void | Promise<void>;
}

sdk.usePlugin(myPlugin);
// deduped by name; onInitialize runs on sdk.initialize(), onDestroy on sdk.destroy()
```

Use `ctx.rpc` to add middleware or `sdk.addEventInterceptor` inside `install`. The offline queue is a plugin - see [Offline Queue](/docs/sdk/offline).

## Module Registry

Register host- or vendor-specific namespaces without modifying the SDK:

```typescript
sdk.registerModule("payments", (rpc) => ({
  charge: (amount: number) => rpc.request("payments", "charge", { amount }),
}));

const payments = sdk.getModule<{ charge: (n: number) => Promise<void> }>("payments");

// Async/lazy variant
sdk.registerLazyModule("analytics", async () => (rpc) => ({ track: (e: string) => rpc.request("analytics", "track", { e }) }));
const analytics = await sdk.getModuleAsync("analytics");
```

`sdk.getMetrics().registeredModules` and `sdk.debug.snapshot().registeredModules` list registered names.

## Instance Registry

Multi-mini-app hosts track live instances in a registry (`getMiniAppSdk()` returns the active
one; `getAllInstances()`, `clearInstances()`, `registerInstance()` exist for multi-tab shells).
This is host-shell machinery - mini apps always read `window.__GSA_SDK__` (or their provider
hook) instead.

## CDN Build

This is how the instance gets to you: the host loads the `@lizuz/sewa-sdk` bundle via a
`<script>` tag (`.../dist/sewa-sdk.min.js`), with a pre-load config on `window.__GSA_SDK__`
carrying at least `{ miniAppId }`. The bundle auto-initializes (handshake + hydration) and then
overwrites the same global with the live instance - which is what your provider polls for.
You never load this script yourself; understand it so the `window.__GSA_SDK__` polling in
[Getting Started](/docs/getting-started) makes sense.
