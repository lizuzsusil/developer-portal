# Platform (`sdk.platform`)

Your mini app runs inside two different shells: a browser page, and the native
Sewa app. `sdk.platform` tells you which one, so you can adjust behaviour that
genuinely differs between them.

Most mini apps never need it. Use CSS media queries for layout. Reach for
`sdk.platform` only when a decision depends on the shell itself.

## The surface

```js
sdk.platform.type;        // "web" | "flutter"

sdk.platform.isWeb();     // running in a browser shell
sdk.platform.isMobile();  // running in the native Sewa app
```

`type` is a property, not a method. The two checks are the whole API.

| Member | Meaning |
|---|---|
| `type` | `"web"` in a browser shell, `"flutter"` in the native app |
| `isWeb()` | `type === "web"` |
| `isMobile()` | `type === "flutter"` |

> `isFlutter()` also exists and is the same check as `isMobile()`. It is named
> after the technology the native shell is built with. Prefer `isMobile()`:
> it describes what your code actually cares about, and it stays correct if
> the shell is ever rebuilt on something else.

There is no separate iOS or Android check, and no phone or tablet check. The
shell reports one of two values. If you need screen size, use a media query.

## When it is the right tool

```js
// Downloads behave differently: the native shell writes to device storage.
if (sdk.platform.isMobile()) {
  await sdk.device.download({ url: receiptUrl });
} else {
  window.open(receiptUrl, "_blank");
}
```

Good reasons to branch:

- A capability exists on one shell only.
- The native shell owns an interaction, such as saving a file or haptics.
- You want to hide a browser-only affordance, such as "open in new tab".

## When it is the wrong tool

Do not use `sdk.platform` to guess whether a capability is available. Ask
directly, because the answer depends on the grant your mini app was given, not
on the shell:

```js
if (sdk.capabilities.includes("device")) {
  // …
}

if (sdk.device.isSupported("biometric")) {
  // …
}
```

A capability your mini app was not granted stays unavailable on both shells.

## Layout

Do not branch on platform for layout. The native shell renders your app in a
web view, so the same CSS applies:

```css
@media (max-width: 600px) { /* narrow, on either shell */ }
```
