# Offline Queue

> **Host-installed.** The offline queue is a plugin the **host** installs on the SDK before handing
> it to your mini app. There is nothing to import or construct — mini apps never see the SDK
> package. This page describes the behavior you can rely on.

Queue capability-gated requests while the host is unreachable and replay them when connectivity returns.

## Behavior

The host configures the queue with an allowlist (default `["storage", "api", "navigation"]`),
a cap (default 50 entries), and a TTL (default 5 min):

| Option | Default | Meaning |
|---|---|---|
| `allowlist` | `["storage","api","navigation"]` | Namespaces to queue |
| `maxEntries` | `50` | Drop oldest beyond this |
| `ttlMs` | `300000` | Drop entries older than this |

When `connection.lost` fires (or `navigator.onLine === false`), matching requests are enqueued
instead of failing. On `connection.established` / `online`, entries flush in order. Expired or
overflowed entries are pruned. Subscribe to `connection.lost` / `connection.established`
(see [Events](/docs/sdk/events)) to reconcile your UI — re-fetch config or flags after a
reconnect.

The plugin is a normal `SdkPlugin` - see [Plugins](/docs/sdk/plugins).
