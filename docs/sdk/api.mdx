# Backend API Gateway (`sdk.api.request`)

The `sdk.api.request("POST", { ... })` module method routes authenticated requests through the host gateway proxy. It is the **only** network entry point - unary calls, chat streaming, and file streaming all go through `request`.


---

## Public Methods

### `request(method, params)`

Executes an authenticated API request through the host gateway. The host concatenates the mini-app `endpoint` route with its own backend base URL and forwards method, headers, and body verbatim.

**Signatures:**

```typescript
// Unary - streaming off by default (covers init + normal calls)
request<T = unknown, B = unknown>(
  method?: string,
  params?: ApiRequestParams<B>,
): Promise<ApiResult<T>>;

// Streaming - returns the host stream for live consumption
request<T = unknown, B = unknown>(
  method: string,
  params: ApiRequestParams<B> & { stream: true },
): Promise<T>;
```

**Parameters (`ApiRequestParams`):**

| Parameter | Type | Required | Default | Description |
|---|---|---|---|---|
| `method` | `string` | No | `"POST"` | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`. |
| `params.endpoint` | `string` | No | - | Mini-app route, e.g. `"/v1/taxes"`. Must be a relative path; the host joins it onto its backend base URL. |
| `params.query` | `Record<string, string>` | No | - | URL query string. Sent on `GET` requests. |
| `params.body` | `B` | No | - | Request payload. Serialized as JSON for non-`GET`/`DELETE` calls. Stays opaque to the SDK - no validation. |
| `params.headers` | `Record<string, string>` | No | - | Extra headers (e.g. `x-mini-app-id`). Mini-app values win over host defaults. |
| `params.stream` | `boolean` | No | `false` | `true` opens a live stream (SSE chat events or file bytes). The mini app interprets the chunks. |
| `params.signal` | `AbortSignal` | No | - | Cancels the unary call or stream; cancelling a stream notifies the host (`api.cancel`). |
| `params.onProgress` | `(p: { uploadedBytes: number; totalBytes?: number }) => void` | No | - | Upload-progress callback, mirrored from the host's `api.uploadProgress` event. |

**Returns:**

| Overload | Type | Description |
|---|---|---|
| Unary | `Promise<ApiResult<T>>` | `{ status, data, headers }`. Non-2xx statuses resolve (not throw) - check `status` yourself. |
| Streaming | `Promise<T>` (a `StreamBuilder`) | Consume via `iterate()` / async iteration, settle with `waitUntilDone()`, stop with `cancel()`. |

### Cancellation

Pass `signal`, or call `builder.cancel()` on a stream. Cancelling notifies the host (`api.cancel`) so it stops producing. Streams are never retried automatically - re-issue the request to resume. See [Streaming](/docs/sdk/stream).

### Errors

- Wrong call shape (e.g. the removed object form) throws `SdkError` with `code: "INVALID_PARAMS"` before any network traffic.
- Transport failures (timeout, unreachable host) reject with the matching `SdkError` subclass - see [Errors](/docs/sdk/errors).
- Backend HTTP errors resolve normally on unary calls (inspect `status`); on streams they arrive as a terminal `{"type": "error", "detail": ...}` chunk.
