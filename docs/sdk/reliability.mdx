# Reliability

> **Host-configured, informational for vendors.** Heartbeat, circuit breaker, and adaptive timeout
> are tuned by the host via SDK options your mini app never passes. Read this to understand the
> behavior you observe (`connection.lost`, `CIRCUIT_OPEN`, background retries) - not to configure it.

Heartbeat, circuit breaker, and adaptive timeout keep the mini app resilient against host stalls.

## Heartbeat

The host configures the heartbeat (defaults: ping every 30 s, expect pong within 5 s,
`connection.lost` after 2 missed pongs):

Events: `connection.lost` / `connection.established` - see [Events](/docs/sdk/events). On `lost`, the SDK re-handshakes with backoff; on `established`, queued work resumes.

## Circuit Breaker

The host configures the circuit breaker (threshold / window / open duration). States:
`closed → open → halfOpen`. While `open`, requests throw `CIRCUIT_OPEN` without hitting the
transport - treat it like a retryable error (see [Errors](/docs/sdk/errors)).

## Adaptive Timeout

The host may enable adaptive timeout, which observes past durations and proposes adjusted
per-action timeouts within a min/max clamp.

## Metrics Backing

See [Observability](/docs/sdk/observability) for `sdk.debug.snapshot().metrics` and `sdk.debug.diagnose()`.
