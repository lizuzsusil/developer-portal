# Getting started

By the end of this page you will have a mini app that reads the signed-in
citizen and calls your backend.

## 1. Export `mount`

Your bundle's entry point exports one function. Sewa calls it with a container
element and gives you back nothing else to wire up:

```js
// src/main.js
export function mount(container, runtime) {
  const sdk = window.__SEWA_SDK__;   // Sewa has already injected it

  container.innerHTML = `<h1>Loading…</h1>`;
  start(container, sdk, runtime?.initialPath);

  return {
    unmount() {
      container.innerHTML = "";
    },
  };
}
```

### What `mount` is given

| Field | What it is |
|---|---|
| `container` | An empty element to render into. It is yours until `unmount` |
| `runtime.initialPath` | Where to open, when the citizen arrived by deep link. Absent on a normal open |
| `runtime.locale` | The citizen's language, e.g. `si-LK`. Also on `sdk.appearance` |
| `runtime.theme` | `"light"` or `"dark"` at mount time |

`window.__SEWA_SDK__` is guaranteed to be present **before** `mount` is called.
You never wait for it, and you never poll for it.

Return an object with `unmount`. Sewa calls it when the citizen leaves, and
anything you do not clean up there leaks for the rest of the session: timers,
listeners, open streams.

## 2. Build as an ES-module library

```js
// vite.config.js
export default {
  build: {
    lib: {
      entry: "./src/main.js",
      formats: ["es"],
      fileName: () => "[name][hash].js",
    },
  },
};
```

You hand Sewa the built bundle. You do not host it — see
[Going live](/docs/going-live).

## 3. Read the citizen

The citizen is already signed in. You never build a login screen.

```js
const user = await sdk.auth.getUser();
// { id: "...", name: "...", ... }  or null
```

See [sdk.auth](/docs/sdk/auth).

## 4. Call your backend

Your frontend does not know your backend's address. Pass the method first,
then the path:

```js
const res = await sdk.api.request("POST", {
  path: "/v1/quota",
  body: { vehicleNumber: "WP CAB-1234" },
});

console.log(res.status, res.data);
```

Sewa looks up the backend registered for your mini app and forwards it there.
See [sdk.api](/docs/sdk/api).

## 5. Handle what you were not granted

Your mini app is granted a specific set of capabilities. Anything outside it
fails immediately rather than hanging:

```js
if (!sdk.capabilities.includes("device")) {
  showManualAddressForm();
  return;
}
```

See [Handling errors](/docs/sdk/errors).

## 6. Run it

Open the [playground](/docs/playground), point it at your dev server and your
backend, and press **Start testing**.

:::note How the SDK reaches you
In production Sewa injects `window.__SEWA_SDK__` before calling `mount`, so
there is nothing to load.

The playground runs your dev server in a frame instead, and cannot inject across
origins. For local testing only, add these two tags to the page you serve:

```html
<script>
  window.__SEWA_SDK__ = {
    miniAppId: new URLSearchParams(location.search).get("miniAppId"),
  };
</script>
<script src="https://cdn.sewa.gov/mini-app-sdk/sewa-sdk.min.js"></script>
```

The bundle replaces that global with the live SDK instance. It connects in the
background and fires no ready event, so wait for it before the first call:

```js
async function whenSdkReady(timeoutMs = 10000) {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const sdk = window.__SEWA_SDK__;
    if (sdk && typeof sdk.debug?.snapshot === "function") {
      const { status } = sdk.debug.snapshot();
      if (status === "ready") return sdk;
    }
    await new Promise((resolve) => setTimeout(resolve, 50));
  }
  throw new Error("The Sewa shell did not answer.");
}

const sdk = await whenSdkReady();
```

Never hard-code `miniAppId`. Sewa tells your app which mini app it is.
:::

## TypeScript

Types are a dev dependency. The SDK runtime still comes from the platform:

<InstallCommandBlock />

```ts
// src/gov-sdk.d.ts
import type { MiniAppSdkInterface } from "@govtech/mini-app-types";

declare global {
  interface Window {
    __SEWA_SDK__?: MiniAppSdkInterface;
  }
}
```
