# Getting Started

The SDK is **injected by the host shell** at `window.__GSA_SDK__` before your app mounts. You do **not** install the SDK runtime. Your app depends only on the shared types package for type-checking; the host provides the live instance at runtime.

> Framework-specific, copy-pasteable walkthroughs live in [React](/docs/integration/react), [Vue](/docs/integration/vue), [Angular](/docs/integration/angular), [Svelte](/docs/integration/svelte), and [Solid](/docs/integration/solid). This page is the framework-agnostic scaffold.

## 2. Export the Mount Entry

The host loads your bundle as an ES module and calls `mount`. Honor the optional `runtime.initialPath` when present (deep links) and return an `unmount` handle:

```typescript
// src/main.ts - shape of the contract (see framework guides for concrete React/Vue/etc. rendering)
export function mount(container: HTMLElement, runtime?: { initialPath?: string }) {
  // render your app into `container` - e.g. createRoot(container).render(<App />)
  // if `runtime?.initialPath` is set, route there on first render
  return { unmount() { /* teardown your framework tree */ } };
}
```

The host owns the SDK instance and destroys it. your app only cleans up its own render tree.

## 3. Build as a Library

Build an ES library and emit the `manifest.json` the host uses for discovery. The `platform` constraints inside the manifest are host-side version metadata, not a bundle dependency.

See your framework guide for the complete `vite.config.ts` + `createManifest` setup:
[React](/docs/integration/react#6-vite-build) · [Vue](/docs/integration/vue#6-vite-build) · [Svelte](/docs/integration/svelte#6-vite-build) - same contract, different framework plugins.

## 4. Verify

Build your application with your framework's build step and confirm `dist/manifest.json` contains `bundle.entry` and `bundle.files` pointing to the emitted assets. Then load the bundle in the [Host Playground](/docs/host-playground) to ensure it mounts and `sdk.*` calls resolve.

All platform access goes through `sdk.*` - no direct `fetch` to platform endpoints. Capability errors and retries are covered in [Errors](/docs/sdk/errors) and [Reliability](/docs/sdk/reliability).
