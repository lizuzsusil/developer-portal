# What a mini app is

*New to Sewa, or not a developer? Start with
[What is a mini app?](/docs/what-is-a-mini-app).*

A mini app is your own web app, running inside the Sewa Citizen app. Citizens
reach it from the Sewa home screen without installing anything.

You write it and you own its backend. Sewa hosts the bundle, provides the
surrounding shell, identifies the citizen, and routes your API calls.

## What you build

An **ES-module bundle that exports `mount`**. Sewa loads it and calls that
function with a container element:

```js
export function mount(container, runtime) {
  // render your app into `container`
  return { unmount() { /* clean up */ } };
}
```

You do not ship an HTML page, and you do not host it. You hand Sewa a bundle.

## What Sewa does at runtime

1. Reads the signed manifest for your mini app: bundle URL, version, SDK
   requirement, and whether you are switched on.
2. Fetches your bundle from the platform CDN and **verifies its hash** against
   the signed manifest. A mismatch is refused.
3. Injects the SDK at `window.__SEWA_SDK__`.
4. Calls your `mount(container, runtime)`.

So by the time your code runs, the SDK is already there. You read it — you never
install or import it.

```js
const sdk = window.__SEWA_SDK__;
const user = await sdk.auth.getUser();
```

## What you get

| What you get | What it means |
|---|---|
| **The signed-in citizen** | Already authenticated. You never build a login screen. |
| **A route to your backend** | You call it by path. Sewa forwards the request. |
| **Device features** | Camera, location, files, biometrics, through one API. |
| **Storage** | A private key-value store, scoped to your mini app. |
| **Theme and language** | Follows the citizen's choice automatically. |

## Two facts that surprise people

- **Your frontend never holds your backend address.** It asks for a path and
  Sewa routes it, so you can move your backend without shipping a new frontend.
- **Your backend never talks to the browser.** Sewa calls it server to server,
  so it needs no CORS configuration for the citizen path.

## Where your bundle lives

Agencies do not self-host mini app bundles. You submit a bundle, the platform
scans it, and it is published to the platform's own signed CDN. That signing is
what lets Sewa trust the code it is about to run.

The [playground](/docs/playground) is the exception, and only for development:
there you point Sewa at a URL you are serving yourself.
