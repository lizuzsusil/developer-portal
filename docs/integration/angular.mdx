# Angular Integration Guide

Angular is a supported framework for Sewa mini apps. This guide starts from a **standard
`ng new` project** and converts it step by step into a **basic, working Angular 21 mini app**:
a Vite ES-library build exporting the host-called `mount`/`unmount` lifecycle, with the SDK
injected by the host via `window.__SEWA_SDK__` and strict lifecycle handling.

By the end you will have a mini app that builds to `dist/` with a `manifest.json` and loads
inside the [Host Playground](/docs/host-playground). Deeper patterns (appearance sync, i18n,
router sync, per-screen feature folders) are covered under
[Going further](#going-further) once the scaffold runs.

> **Version used here: Angular 21** (`@angular/* ^21.0.0`, TypeScript `~5.9`, zoned with
> `zone.js`). Icons use `@lucide/angular 1.47.0` - the legacy `lucide-angular` package is
> deprecated, and the new package peers on `@angular/core >= 17` with no upper bound.

> **Reading this guide:** shell commands offer a package-manager selector (npm / pnpm / yarn /
> bun) and code samples offer a TypeScript / JavaScript selector. Each selector acts on its
> own block only - changing one never flips the others on the page. The scaffold itself is
> TypeScript - Angular requires TS for decorators and AOT compilation - the JavaScript tabs
> show the equivalent untyped logic for comparison.

> **No runtime install.** A Sewa mini app must **not** `npm install` or `import` the SDK
> runtime. The host shell injects the SDK instance as `window.__SEWA_SDK__` at runtime. Your
> app only needs the shared types package as a dev dependency for compile-time safety.

## Step 3 - Add the scripts and the emit config

Add two scripts to `package.json` (keep the stock `start` for daily dev - Step 7):

```json
{
  "scripts": {
    "typecheck": "ngc -p tsconfig.app.json",
    "build:miniapp": "ngc -p tsconfig.app.json && ngc -p tsconfig.emit.json && vite build --config vite.lib.config.ts"
  }
}
```

- `typecheck` runs Angular's template + TypeScript checking (fails on errors).
- `build:miniapp` typechecks, AOT-emits to `ngc-out/`, then bundles the ES library +
  `manifest.json`. (The stock `build` script runs `ng build`, which emits an
  `index.html`-centric app bundle - **not** what the host loads. `build:miniapp` replaces it
  for production; see Step 8.)

The stock `tsconfig.app.json` works for typechecking as-is **except** its `"types": []`,
which hides Node builtins from the manifest plugin. Change that one line:

```json
// tsconfig.app.json - edit the stock file, one line:
{
  "compilerOptions": {
    "types": ["node"]
  }
}
```

Then add the emit overlay `ngc` uses to output compilable JavaScript for Vite to bundle.
`moduleResolution: bundler` is required - the stock base config uses `module: preserve`
without it, and the emit breaks without this line:

```json
// tsconfig.emit.json - new file at the project root
{
  "extends": "./tsconfig.app.json",
  "compilerOptions": {
    "module": "ESNext",
    "moduleResolution": "bundler",
    "noEmit": false,
    "declaration": false,
    "outDir": "ngc-out"
  }
}
```

## Step 4 - Add the manifest plugin and the production Vite config

`ng build` can't produce the host contract, so production goes through `vite.lib.config.ts`
plus a small `createManifest` plugin. Both are new files; `angular.json` stays untouched.

<CodeTabs groupId="angular-code-manifest"
  typescript={`// src/app/utils/createManifest.ts - writes the host-discovery manifest.json
import fs from "node:fs";
import path from "node:path";
import type { Plugin } from "vite";

const pkgPath = path.resolve(process.cwd(), "package.json");
const pkg = JSON.parse(fs.readFileSync(pkgPath, "utf-8"));

export function createManifest(): Plugin {
  return {
    name: "custom-manifest",
    async writeBundle(options) {
      const outDir = options.dir || "dist";

      // Vite writes its manifest to .vite/ by default, but \`manifest:
      // "manifest.json"\` in the lib config below puts it at the output root.
      const possibleManifestPaths = [
        path.resolve(outDir, "manifest.json"),
        path.resolve(outDir, ".vite/manifest.json"),
      ];
      const originalManifestPath = possibleManifestPaths.find((p) => fs.existsSync(p));
      if (!originalManifestPath) return;

      const viteManifest = JSON.parse(fs.readFileSync(originalManifestPath, "utf-8"));
      const entryKey = Object.keys(viteManifest).find((key) => viteManifest[key].isEntry);
      const entryItem = entryKey ? viteManifest[entryKey] : null;

      const collectFiles = (dir: string, acc: string[] = []): string[] => {
        for (const file of fs.readdirSync(dir)) {
          const full = path.join(dir, file);
          if (fs.statSync(full).isDirectory()) {
            collectFiles(full, acc);
          } else {
            const rel = path.relative(outDir, full).replace(/\\\\/g, "/");
            if (!rel.endsWith("manifest.json")) acc.push(rel);
          }
        }
        return acc;
      };

      const customManifest = {
        schemaVersion: "1",
        framework: "angular",
        application: {
          id: pkg.name || "my-mini-app",
          name: pkg.name || "my-mini-app",
          version: pkg.version || "0.0.0",
          type: "mini-app",
        },
        platform: {
          runtime: "^1.0.0",
          sdk: "^1.0.9",
        },
        bundle: {
          entry: entryItem?.file || "",
          styles: entryItem?.css || [],
          files: collectFiles(outDir),
        },
      };

      if (
        originalManifestPath.includes(".vite") &&
        fs.existsSync(originalManifestPath)
      ) {
        fs.unlinkSync(originalManifestPath);
      }
      fs.writeFileSync(
        path.resolve(outDir, "manifest.json"),
        JSON.stringify(customManifest, null, 2),
      );
    },
  };
}`}

**2. New SDK service at `src/app/core/sdk.service.ts`.** Polls for the host-injected SDK and
publishes a `phase` signal (`loading | ready | error`):

<CodeTabs groupId="angular-code-sdk"
  typescript={`// src/app/core/sdk.service.ts - new file
import { Injectable, signal } from "@angular/core";

export type SdkPhase = "loading" | "ready" | "error";

@Injectable({ providedIn: "root" })
export class SdkService {
  readonly phase = signal<SdkPhase>("loading");
  sdk: MiniAppSdk | null = null;

  constructor() {
    void this.waitForSdk();
  }

  private async waitForSdk(): Promise<void> {
    for (let attempt = 0; attempt < 30; attempt++) {
      const sdk = window.__SEWA_SDK__;
      if (sdk) {
        this.sdk = sdk;
        this.phase.set("ready");
        return;
      }
      await new Promise((r) => setTimeout(r, 500));
    }
    this.phase.set("error");
  }
}`}
  javascript={`// src/app/core/sdk.service.js - new file

**4. Replace `src/main.ts`.** The stock `bootstrapApplication(App, appConfig)` becomes the
host-called `mount`/`unmount` pair - reusing the stock `appConfig` as-is via
`createApplication(appConfig)`:

<CodeTabs groupId="angular-code-main"
  typescript={`// src/main.ts - replace the stock bootstrap
import "zone.js";
import type { ApplicationRef } from "@angular/core";
import { createApplication } from "@angular/platform-browser";
import { appConfig } from "./app/app.config";
import { App } from "./app/app";

const mounted = new WeakMap<HTMLElement, { appRef: ApplicationRef; host: HTMLElement }>();

/** Sets the initial hash so the router starts at the host-provided path. */
function applyInitialHash(initialPath?: string) {
  if (!initialPath) return;
  const normalized = initialPath.startsWith("/") ? initialPath : \`/\${initialPath}\`;
  if (!window.location.hash || window.location.hash === "#" || !window.location.hash.startsWith("#/")) {
    window.location.replace(\`#\${normalized}\`);
  }
  // If the host already set the hash (e.g. deep link), leave it alone.
}

export async function mount(container: HTMLElement, runtime?: { initialPath?: string }) {
  // Seed the hash BEFORE bootstrap: the router reads the start location
  // during initialization.
  applyInitialHash(runtime?.initialPath);

  const appRef = await createApplication(appConfig);
  const host = document.createElement("app-root");
  container.appendChild(host);
  appRef.bootstrap(App, host);
  mounted.set(container, { appRef, host });
}

/** Host-called teardown. The host loader calls this directly. */
export function unmount(container: HTMLElement): void {
  const entry = mounted.get(container);
  if (!entry) return;
  entry.appRef.destroy();
  entry.host.remove();
  mounted.delete(container);
}

// Local dev only (ng serve): the host is absent, so mount into the page.
if (import.meta.env.DEV) {
  void mount(document.body);
}`}

Three details differ from React/Vue and all three matter:

- **`mount` is async** (`createApplication` returns a promise). The host ignores the return value
  and uses the module-level `unmount(container)` export instead.
- **`unmount` is a real export**, tracked per container in a `WeakMap`.
  `ApplicationRef.destroy()` plus host-node removal is the only leak-free teardown - unlike
  React/Vue, DOM removal alone is not enough.
- **State lives in root-provided services** (`providedIn: "root"` singletons like
  `SdkService`), so it survives route changes once you add screens.

## Going further

Once the converted app loads, grow it with these patterns (all covered in the sections below).

### Core services

`src/app/core/` holds platform wiring only - no UI, no feature logic. All services are
`providedIn: "root"` singletons. Beyond the `SdkService` from Step 6:

- **AppearanceService** - holds `locale` / `theme` computed signals seeded from
  `sdk.appearance.state()`. An `effect` starts the `sdk.appearance.subscribe()` subscription
  the moment the SDK signal becomes ready - no lifecycle-ordering assumptions - and
  unsubscribes on destroy.
- **I18nService** - loads the `en` / `si` / `ta` JSON dictionaries, selects by
  `locale.language` with `en` fallback, and interpolates `{param}` placeholders. Components
  call `i18n.t('home.badge')` directly in templates.
- **HostRouterService** - subscribes to `router.events`, emits
  `navigation.route.changed` with `canGoBack` derived from "is the route root?", syncs
  immediately on start when booting off-root (deep link - seeded by `applyInitialHash` in
  `main.ts`), and answers `navigation.back.requested` via `Location.back()`. Every
  `sdk.navigation.router.*` call is guarded with `?.` because some mobile hosts don't
  implement the router bridge. Advantage over React/Vue: PUSH vs POP uses Angular's native
  `NavigationStart.navigationTrigger` (`'imperative'` vs `'popstate'`) - no approximation
  needed.

### Feature segregation + routing

Each screen is a folder with a stateful service plus thin components - the service owns
signals and SDK/browser calls, the component only binds `svc.x()` and
`(click)="svc.method()"`. Because services are singletons, tab state survives route changes
while each feature stays independently testable. Presentational cards take data via `@Input`
(icons as standalone component references, e.g. `LucideCpu` from `@lucide/angular`) and emit
via `@Output`:
