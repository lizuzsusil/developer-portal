# Vue 3 Integration Guide

<FrameworkBadge framework="vue" status="active" />

> **Package:** no framework runtime package - Vue 3 + vue-router from npm, types from the shared types package, and the host-injected SDK at runtime. This guide documents the Vue 3 integration pattern for Sewa mini apps.

Vue 3 is a supported framework for Sewa mini apps. The pattern mirrors React one-to-one: a Vite ES-library build exporting `mount(container, runtime?)`, host-injected SDK via `window.__GSA_SDK__`, and a provider component with strict lifecycle handling - expressed with Vue idioms (Composition API, `provide`/`inject`, vue-router hash history).

## 3. Entry Points

### `main.ts` - host-callable mount

```typescript
// src/main.ts
import { createApp } from "vue";
import { createRouter, createWebHashHistory } from "vue-router";
import App from "./App.vue";
import MiniApp from "./components/MiniApp/index.vue";
import "./style.css";
import Test from "./components/Test.vue";

const routes = [
  {
    path: "/", component: MiniApp
  },
  {path: '/test', component: Test}
]

const router = createRouter({
  history: createWebHashHistory(),
  routes
})

/** Sets the initial hash so the hash history starts at the host-provided path. */
function applyInitialHash(initialPath?: string) {
  if (!initialPath) return;
  const normalized = initialPath.startsWith("/")
    ? initialPath
    : `/${initialPath}`;
  if (
    !window.location.hash ||
    window.location.hash === "#" ||
    !window.location.hash.startsWith("#/")
  ) {
    window.location.replace(`#${normalized}`);
  }
  // If the host already set the hash (e.g. deep link), leave it alone.
}

export function mount(
  container: HTMLElement,
  runtime?: { initialPath?: string },
) {
  // Seed the hash BEFORE the router is installed: vue-router snapshots the
  // start location at install/mount, so a host-provided initialPath applied
  // afterwards would be overwritten by the initial navigation resolving to /.
  applyInitialHash(runtime?.initialPath);

  const app = createApp(App);
  app.use(router);
  app.mount(container);

  return {
    unmount() {
      app.unmount();
    },
  };
}

// Dev-only bootstrap so `vite dev` / `vite preview` render without a host.
// The branch is statically false in the production library build.
if (import.meta.env.DEV) {
  const el = document.getElementById("app");
  if (el) mount(el);
}
```

Two details differ from React and both matter:

- **The router is created per `mount()` call** (`createMiniAppRouter()` factory). A router instance must not be shared across Vue apps - the host may mount, unmount, and remount the mini app.
- **The hash is seeded before `app.use(router)`.** vue-router snapshots the start location at install; applying `initialPath` afterwards gets overwritten by the initial navigation resolving to `/`, silently breaking host deep links.

## 4. SDK State & Provider

`src/plugins/sdk.ts` holds the injection key and state shape (the counterpart of React's `SDKContext`):

```typescript
// src/plugins/sdk.ts
import type { InjectionKey } from "vue";

export interface SdkState {
  sdk: MiniAppSdk | null;
  user: SdkPlatformUser | null;
  isReady: boolean;
  error: Error | null;
}

export const SdkKey: InjectionKey<SdkState> = Symbol("sdk");
```

`PlatformSDKProvider.vue` creates a `reactive<SdkState>`, `provide`s it, and gates rendering on three phases - identical to the React provider:

1. **loading** - polls `window.__GSA_SDK__` with retry (30 × 500 ms), waits on the `__GSA_SDK_READY__` event, then fetches the user. Renders `Connecting to platform...`.
2. **ready** - provides state, mounts a renderless `HostRouterSync` component (which runs `useHostRouter()`), and renders the default slot.
3. **error** - renders `LoadError` with the failure message.

```vue
//src/PlatformSDKProvider.vue
<script setup lang="ts">
import { onUnmounted, provide, reactive } from "vue";
import type { SdkState } from "../plugins/sdk";
import { SdkKey } from "../plugins/sdk";
import { retry } from "../utils/retry";
import HostRouterSync from "./HostRouterSync.vue";
import LoadError from "./LoadError.vue";

const state = reactive<SdkState>({
  sdk: null,
  user: null,
  isReady: false,
  error: null,
});

provide(SdkKey, state);

function getSDK(): MiniAppSdk {
  const instance = window.__GSA_SDK__ ?? null;
  if (!instance) throw new Error("SDK not available");
  return instance;
}

const controller = new AbortController();

async function init() {
  try {
    const instance = await retry(() => getSDK(), {
      maxAttempts: 30,
      delayMs: 500,
      signal: controller.signal,
    });
    await new Promise<void>((res) => {
      if (window.__GSA_SDK__) return res();
      window.addEventListener("__GSA_SDK_READY__", () => res(), {
        once: true,
      });
    });
    const user = await instance.auth.getUser();
    if (!controller.signal.aborted) {
      state.sdk = instance;
      state.user = user ?? null;
      state.isReady = true;
    }
  } catch (error) {
    if (!controller.signal.aborted) {
      state.error =
        error instanceof Error
          ? error
          : new Error("SDK initialization failed");
    }
  }
}

void init();

onUnmounted(() => {
  controller.abort();
});
</script>

<template>
  <LoadError v-if="state.error" :message="state.error.message" />
  <div v-else-if="!state.isReady">Connecting to platform...</div>
  <template v-else>
    <HostRouterSync />
    <slot />
  </template>
</template>
```

Cleanup mirrors `AbortController` semantics via `onUnmounted(() => controller.abort())`.

## 5. Composables



### `usePlatformSDK` - guarded access

```typescript
// src/composables/usePlatformSDK.ts
import { inject } from "vue";
import { SdkKey, type SdkState } from "../plugins/sdk";

export function usePlatformSDK(): SdkState & { sdk: MiniAppSdk } {
  const state = inject(SdkKey, null);
  if (!state?.sdk) {
    throw new Error("usePlatformSDK must be used within PlatformSDKProvider");
  }
  return state as SdkState & { sdk: MiniAppSdk };
}
```

Returning the reactive state object (rather than destructured values) preserves reactivity for `user` / `isReady` downstream.

### `useAppearance` - theme/locale sync

Keeps a `reactive<AppearanceState>` seeded from `sdk.appearance.state()`, refreshes it `onMounted`, and subscribes - unsubscribing `onUnmounted`. Returns `{ locale, theme }` as computed refs, so templates use `theme.mode` directly.

### `useHostRouter` - bidirectional navigation sync

Same responsibilities as the React hook - emit `navigation.route.changed` with `canGoBack` derived from "is the route root?", answer `navigation.back.requested` via `router.back()`, and guard every `sdk.navigation.router.*` call with `?.` because some mobile hosts don't implement the router bridge. Two Vue-specific notes:

```typescript
 //src/composables/useHostRouter.ts
 import { onMounted, onUnmounted, ref, watch } from "vue";
import { useRoute, useRouter } from "vue-router";
import { usePlatformSDK } from "./usePlatformSDK";

export const NAVIGATION_EVENTS = {
  BACK_REQUESTED: "navigation.back.requested",
  ROUTE_CHANGED: "navigation.route.changed",
} as const;

function isRootPath(path: string): boolean {
  return path === "/" || path === "";
}

export function useHostRouter() {
  const { sdk, isReady } = usePlatformSDK();

  const route = useRoute();
  const router = useRouter();

  let popping = false;
  const initialized = ref(false);
  const previousPath = ref(route.path);

  function emitRouteChanged(previous: string, current: string) {
    const canGoBack = !isRootPath(current);
    sdk.emit(NAVIGATION_EVENTS.ROUTE_CHANGED, {
      previous,
      current,
      canGoBack,
    });
    previousPath.value = current;
    return canGoBack;
  }

  function syncCurrent(first: boolean, isPop = false) {
    const current = route.path;
    if (!sdk) return;
    if (first) {
      previousPath.value = current;
      // Sync host immediately on first mount if not at root (e.g. deep link)
      if (!isRootPath(current)) {
        emitRouteChanged(current, current);
        // Guard: don't crash if the mobile host hasn't
        // implemented the router bridge.
        void sdk.navigation.router?.push?.(true);
      }
      return;
    }
    emitRouteChanged(previousPath.value, current);
    // Mobile hosts may not implement sdk.navigation.router; guard so that
    // the absence of a router bridge on the host does not crash rendering.
    // POPs never push: the host already counted this entry on the way in.
    if (!isRootPath(current) && !isPop) {
      void sdk.navigation.router?.push?.(true);
    }
  }

  async function goBack() {
    const consumed = !isRootPath(route.path);
    await sdk?.navigation.router?.back?.(consumed);
    if (consumed) {
      // Mark the in-flight navigation as a POP. The route watcher consumes
      // and clears the flag, so classification is deterministic — no timers.
      popping = true;
      router.back();
    }
  }

  // First-mount sync (mirrors the first-navigation branch).
  onMounted(() => {
    syncCurrent(true);
    initialized.value = true;
  });

  // Keep the host's back-button policy in sync with this app's history,
  // otherwise the host never knows a route was pushed and exits on back.
  watch(
    () => route.fullPath,
    () => {
      if (!initialized.value) return;
      const wasPop = popping;
      popping = false;
      syncCurrent(false, wasPop);
    },
  );

  // Sync host when SDK becomes ready — pushes that happened before the
  // bridge was ready never informed the host.
  watch(
    () => isReady,
    (ready) => {
      if (!ready || !sdk) return;
      if (!isRootPath(route.path)) {
        emitRouteChanged(previousPath.value, route.path);
        void sdk.navigation.router?.push?.(true);
      }
    },
  );

  let offBackRequested: (() => void) | undefined;
  onMounted(() => {
    if (!sdk || !isReady) return;
    const off = sdk.on(NAVIGATION_EVENTS.BACK_REQUESTED, () => {
      void goBack();
    });
    if (typeof off === "function") offBackRequested = off;
  });

  onUnmounted(() => {
    offBackRequested?.();
  });

  return { goBack };
}

```

- vue-router exposes no navigation-type API, so PUSH vs POP is approximated: navigations triggered by the composable's own `goBack()` count as POPs, everything else as PUSHes. The flag is consumed and cleared by the route watcher (deterministic, no timers).
- It runs inside the renderless `HostRouterSync.vue` child of the provider, so back-button sync is always active once the SDK is ready.

### Sidebar routing gotcha - always navigate through vue-router

vue-router listens only to `popstate`, never `hashchange`, and drives the URL via `pushState`. A native anchor jump therefore changes the hash **behind the router's back**: its internal location desyncs, and the next programmatic navigation first replaces the URL with the stale route - visible as a "reset to root". Sidebar links must call the `RouterLink` slot's `navigate()`:

```vue
<RouterLink :to="path" custom v-slot="{ isActive, href, navigate }">
  <!-- navigate() routes through vue-router (pushState + state). -->
  <a :href="href" :class="..." @click="(event) => onNavClick(event, navigate)">
    ...
  </a>
</RouterLink>
```

```typescript
function onNavClick(event: MouseEvent, navigate: (event?: MouseEvent) => void) {
  if (window.innerWidth < 768) {
    emit("toggle"); // close the sidebar on mobile
  }
  // Handles preventDefault for plain left clicks; lets modifier-clicks
  // fall through to native behavior.
  navigate(event);
}
```

### `useT` - locale dictionaries

Loads the `en` / `si` / `ta` JSON dictionaries, selects by `locale.language`, falls back to `en` then to the key, and interpolates `{param}` placeholders. Returns computed refs, so templates call `t('home.badge')` directly.

## 6. Extra codes you need (NOTE:You can manage these code as per your needs)

```typescript
//src/utils/errorDetails.ts

export interface ErrorDetails {
  message: string;
  functionName?: string;
  file?: string;
  line?: number;
  column?: number;
  stack?: string;
}

export function parseErrorDetails(error: Error): ErrorDetails {
  const frame = parseFirstStackFrame(error.stack);
  return {
    message: error.message || "Something went wrong while rendering.",
    functionName: frame?.functionName,
    file: frame?.file,
    line: frame?.line,
    column: frame?.column,
    stack: error.stack,
  };
}

function parseFirstStackFrame(stack?: string) {
  if (!stack) return undefined;

  const frameRe = /^\s+at\s+(?:(.+?)\s+\()?(.+?):(\d+):(\d+)\)?$/;
  for (const line of stack.split("\n")) {
    const match = line.match(frameRe);
    if (match) {
      return {
        functionName: match[1]?.replace(/^Object\./, ""),
        file: match[2],
        line: Number(match[3]),
        column: Number(match[4]),
      };
    }
  }
  return undefined;
}

//src/components/ErrorBoundary.vue

<script setup lang="ts">
import { onErrorCaptured, ref } from "vue";
import type { ErrorDetails } from "../utils/errorDetails";
import { parseErrorDetails } from "../utils/errorDetails";
import LoadError from "./LoadError.vue";

const details = ref<ErrorDetails | null>(null);

onErrorCaptured((error) => {
  console.error(
    "ErrorBoundary caught an error:",
    error,
  );
  details.value = parseErrorDetails(
    error instanceof Error ? error : new Error(String(error)),
  );
  // Stop propagation: this boundary renders the fallback itself.
  return false;
});
</script>

<template>
  <LoadError v-if="details" :details="details" />
  <slot v-else />
</template>
```

## 7. Vite Build

Same library contract as React - Vue plugin instead of the React plugin, `VueMiniApp` as the lib name, and `framework: "vue"` in the emitted manifest:

```typescript
// vite.config.ts
import tailwindcss from "@tailwindcss/vite";
import vue from "@vitejs/plugin-vue";
import { defineConfig } from "vite";
import { createManifest } from "./src/utils/createManifest.ts";

export default defineConfig({
  plugins: [vue(), tailwindcss(), createManifest()],
  define: { "process.env.NODE_ENV": JSON.stringify("production") },
  build: {
    target: "chrome89",
    manifest: "manifest.json",
    outDir: "dist",
    cssCodeSplit: true,
    lib: {
      entry: "./src/main.ts",
      name: "VueMiniApp",
      formats: ["es"],
      fileName: () => "[name][hash].js",
    },
    rollupOptions: {
      output: {
        codeSplitting: false,
        format: "es",
        chunkFileNames: "assets/[name]-[hash].js",
        assetFileNames: "assets/[name]-[hash][extname]",
      },
    },
  },
  server: {
    host: "0.0.0.0",
    cors: true,
    headers: { "Access-Control-Allow-Origin": "*" },
  },
});
```

The `createManifest` plugin is a straight port of the React one: it reads Vite's manifest, finds the entry, collects all `dist` files, and writes the host-discovery `manifest.json` with `framework: "vue"`. As on React, `platform.runtime` / `platform.sdk` are host-side version constraints, not bundle dependencies - the bundle ships zero SDK code.

### Router table

`src/router.ts` mirrors the React `<Routes>` table one-to-one (hash history, catch-all redirect), including its quirks - `/images` and `/router` have sidebar entries but no route, so they fall through to `/`:

```typescript
// src/router.ts
import { createRouter, createWebHashHistory } from "vue-router";
import TabHome from "./components/TabHome.vue";
// ... one import per tab

export function createMiniAppRouter() {
  return createRouter({
    history: createWebHashHistory(),
    routes: [
      { path: "/", component: TabHome },
      { path: "/test-api", component: TabTestApi },
      { path: "/chat", component: TabChat },
      { path: "/location", component: TabLocation },
      { path: "/camera", component: TabCamera },
      { path: "/gallery", component: TabGallery },
      { path: "/files", component: TabFiles },
      { path: "/download", component: TabDownload },
      { path: "/contact", component: TabContacts },
      { path: "/biometric", component: TabBiometric },
      { path: "/:pathMatch(.*)*", redirect: "/" },
    ],
  });
}
```

Routed tabs receive their props from the shell (`MiniApp/index.vue`) via `<RouterView v-slot>` + a per-path props object - preserving the React architecture where tab state lives above the route switch and survives tab changes.

## 8. Essential folder structure

The canonical Vue layout for a mini app - entry contract, SDK state, composables, and build manifest. Only the load-bearing files are shown; feature tabs and cards live under `components/`:

```
vue-mini-app/
├── index.html              # Vite dev entry - single <div id="app">
├── package.json            # dependencies + scripts
├── vite.config.ts          # Vite lib mode + manifest plugin
├── tsconfig.app.json       # app TS config (referenced by tsconfig.json)
├── public/                 # static assets
└── src/
    ├── main.ts             # ← mount(container, runtime?)
    ├── App.vue             # ← ErrorBoundary + Provider + shell
    ├── router.ts           # ← per-mount hash-history factory
    ├── routes.ts           # sidebar nav items
    ├── index.css           # Tailwind + custom styles
    ├── global.d.ts        # ← host-injected SDK typings
    ├── components/         # tabs, cards, shell, provider, Sidebar
    ├── composables/        # usePlatformSDK, useAppearance, useHostRouter, useT
    ├── plugins/            # sdk.ts (SdkKey injection wiring)
    ├── types/              # shared interfaces (index.ts)
    ├── utils/              # createManifest.ts, retry.ts, errorDetails.ts
    └── i18n/               # en / si / ta dictionaries
```
